# DAG-agent v3.2.1 技术预览版使用指南

> 本文是当前公开使用指南。命令以 Windows PowerShell 为主；Linux/macOS 只采用 CI 实际覆盖的声明。真实执行可能产生供应商费用，零模型运行不需要 API Key。

## 1. 安装与命令

要求 Python 3.11+。从 GitHub 源码安装：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install .
```

或先下载 GitHub Release wheel，再执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install .\dag_agent-3.2.1-py3-none-any.whl
```

当前不发布到 PyPI。安装后有三个入口：

- `dag-agent-mcp`：v3 SQLite + MCP + 调度 + 验收 + Obsidian；
- `dag-agent-full50`：固定模板的 50 节点全流程基准；
- `dag-agent`：v1 历史兼容 CLI，无 checks 时可仅凭 summary 通过，不具备 v3 的 fail-closed 语义。

默认数据位置：

- v3：`~/.dag-agent/v3/missions`，可用 `DAG_AGENT_V3_HOME` 覆盖；
- v1：`~/.dag-agent/v1/missions`，可用 `DAG_AGENT_HOME` 或 `dag-agent --home` 覆盖；
- full50：当前工作目录的 `dag-agent-runs/full50/`，建议始终显式传 `--output`。

## 2. 零模型完整流程

```powershell
$env:PYTHONUTF8 = "1"
dag-agent-full50 --mode zero-model --output .\zero-model-demo
```

每次使用新的空目录。成功时退出码为 0，`zero-model-demo/run_results.json` 应包含 `success=true`、50 节点、12 次拆分、50 accepted、`done/machine`，并且全部 checks 为 true。

该结果验证平台机制链路，不调用真实模型，也不证明业务内容质量。任务结构、输出和恢复示例见 [FULL_TASK_GUIDE.md](../techstack_full_v2/FULL_TASK_GUIDE.md)。

## 3. v3 MCP 使用

MCP 注册示例：

```json
{
  "mcpServers": {
    "dag-agent-v3": {
      "command": "C:\\path\\to\\.venv\\Scripts\\dag-agent-mcp.exe",
      "env": {"DAG_AGENT_V3_HOME": "D:\\dag-agent-data\\v3"}
    }
  }
}
```

把路径替换为你的可写目录。最小工具顺序：

```text
dag3_create_mission(name, brief, template="research")
dag3_add_node(...) / dag3_decompose(...)
dag3_run_start(mid, real=False, auto_split=True)
dag3_run_status(mid)
dag3_board(mid)
dag3_run_stop(mid, mode="drain" 或 "kill")
```

看板位置以 `dag3_board` 返回的 `overview` 为准。自动生长默认开启，可传 `auto_split=False` 关闭。

### 供应商暂停恢复

`quota_exhausted`、`balance_exhausted`、`auth_failed` 会持久暂停。处置后通过同一个 MCP 工具面确认恢复：

```text
dag3_run_start(mid, ..., provider_pause_ack=True)
```

阻塞式 `dag3_run(..., provider_pause_ack=True)` 同样支持。无确认会拒绝启动；后端预检失败时暂停仍然保留。

### 停止语义

- `drain`：不再派发，在途有界结束；
- `kill`：drain + 取消在途尝试，并请求当前后端终止进程树；以 `stopped=True` 和调度线程退出为完成依据。

MCP 进程内的 `RunManager` 句柄不能直接用来控制另一进程。full50 标准 CLI 没有跨进程 `stop` 子命令；外部强杀驱动后，应先检查是否仍有执行 CLI 子进程，再恢复任务。

## 4. 真实后端（可选）

真实模式需要外部 CLI、供应商凭据和人工预算决策。`--backend-options` 只接受 JSON **文件路径**。

### Claude CLI 兼容后端

安装可用的 Claude Code CLI，并准备不入库的 `.env.local`：

```dotenv
ANTHROPIC_BASE_URL=<供应商 Anthropic 兼容端点>
ANTHROPIC_AUTH_TOKEN=<你的密钥>
ANTHROPIC_MODEL=<供应商支持的模型名>
```

`claude-options.json`：

```json
{"env_file": ".env.local", "timeout": 1500}
```

运行：

```powershell
dag-agent-full50 --mode real --backend-name claude-cli `
  --backend-options .\claude-options.json --output .\real-claude-demo
```

缺少 CLI、端点或凭据时，预检必须失败。不要把 `.env.local` 提交到 Git。

### Pi CLI 后端

本机历史接入验证使用 `@earendil-works/pi-coding-agent@1.5.0`：

```powershell
npm install -g @earendil-works/pi-coding-agent@1.5.0
```

`~/.pi/agent/models.json` 使用 `$BIGMODEL_API_KEY` 环境变量插值，不写入真实 key：

```json
{
  "providers": {
    "glm": {
      "baseUrl": "https://open.bigmodel.cn/api/anthropic",
      "api": "anthropic-messages",
      "apiKey": "$BIGMODEL_API_KEY",
      "models": [{
        "id": "GLM-5.3-Flash",
        "name": "GLM-5.3-Flash",
        "reasoning": false,
        "input": ["text"],
        "contextWindow": 128000,
        "maxTokens": 16384
      }]
    }
  }
}
```

`pi-options.json` 可只写 `{"timeout": 1500}`，再运行：

```powershell
dag-agent-full50 --mode real --backend-name pi-cli `
  --backend-options .\pi-options.json --output .\real-pi-demo
```

Pi 回执分别记录 `pi_session_id`、`response_id`、`agent_id`；tokens 是 CLI 事件流记账，费用为本地估计时标为 `estimated`，不冒充供应商 reported。历史 50 节点真实运行证据不等于当前 3.2.1 修订已重新进行真实供应商验收。

## 5. full50 恢复

```powershell
dag-agent-full50 --resume --output <原运行目录>
```

恢复会沿用 accepted、预算、拆分额度和不可变绝对截止时间，并核对冻结材料、模板、代际及后端配置。已完成任务幂等返回且零执行调用。供应商暂停处置后：

```powershell
dag-agent-full50 --resume --output <原运行目录> --pause-ack
```

结果写入 `resume_results.json`；结果写盘失败应返回非零并保留 fallback 证据。

## 6. 根交付核验

数据库是首选权威锚。先切换到待验根发布物副本目录，否则检查器会核验错误的 cwd：

```powershell
Set-Location <独立根发布物副本目录>
python <原运行目录>\frozen\checks.py --stage root `
  --manifest <原运行目录>\frozen\manifest.json `
  --trusted-db <原运行目录>\mission.db
```

无库离线重放前，由平台/审计方使用现有导出函数生成可信材料：

```powershell
@'
from techstack_full_v2.checks import export_trusted
export_trusted(r"<原运行目录>\mission.db", r"<受控目录>\trusted-export.json", r"<受控目录>\trusted-export.digest.json")
'@ | python -
```

然后在根发布物副本目录执行：

```powershell
python <原运行目录>\frozen\checks.py --stage root `
  --manifest <原运行目录>\frozen\manifest.json `
  --trusted <受控目录>\trusted-export.json `
  --trusted-digest <受控目录>\trusted-export.digest.json
```

digest 与 JSON 必须由审计方保管在执行者不可写的位置。纯离线“导出 + digest”仍可被整体伪造，不能解释为 OS 级认证。

## 7. 公开源码验证与发布工程

在公开源码根目录：

```powershell
python -m pip install ".[dev]"
python -m pytest tests techstack_full_v2/tests techstack_research_v2/tests -m "not slow" --basetemp=work/tmp-pytest/public -q
python -m pytest tests techstack_full_v2/tests techstack_research_v2/tests -m slow --basetemp=work/tmp-pytest/public-slow -q
python scripts/publication_scan.py --self-test
```

严格模式要求工作区与 Git blob 原始字节一致。Windows 若启用 `core.autocrlf`，先创建一个新的字节固定干净检出（目标目录必须不存在）：

```powershell
git -c core.autocrlf=false clone . .\work\release-source-byte-clean
Set-Location .\work\release-source-byte-clean
python scripts/export_release_subset.py --require-clean --out .\release_subset\dag-agent-v3.2.1
$head = git rev-parse HEAD
if ($LASTEXITCODE -ne 0) { throw "git rev-parse failed" }
python scripts/verify_release.py .\release_subset\dag-agent-v3.2.1 --source-repo . --expected-commit $head
if ($LASTEXITCODE -ne 0) { throw "release verification failed" }
```

严格模式包含换行字节差异；不会把 CRLF/LF 归一化后称为“逐字节相同”。构建 wheel 与 sdist：

```powershell
Set-Location .\release_subset\dag-agent-v3.2.1
python -m build
```

## 8. 故障排查与边界

| 现象 | 处理 |
|---|---|
| Windows 控制台 GBK 解码失败 | 设置 `$env:PYTHONUTF8="1"` |
| 真实节点派发前被拒绝 | 检查五段简报与后端预检 |
| `receipt_status=incomplete` | 用量、费用或终态证据不完整，不补零冒充 |
| resume 报配置/模板/代际漂移 | 恢复原版本和配置，或按新任务重新运行 |
| `provider_paused` | 处置额度/余额/认证后显式 ack |
| 预算停派 | 这是调度阈值，不是最终账单硬封顶 |

固定模板生长不等于通用自由规划；机器验收不等于业务事实审查；命令白名单与快照不等于 OS 沙箱。安全报告见 [SECURITY.md](../SECURITY.md)，贡献与发布规则见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
