# 协议 03：提交身份与两阶段接收——v3.2 冻结版

> 冻结日期：2026-10-03。修订五步第 1/2 步最小协议之三。

版本：F1（冻结）

## 1. 目的

修复"慢验收期间取消/改目标/维修/收割被旧提交覆写"。提交权、版本与内容在
**正式接收事务内重新核验**；检查前冻结候选产物，检查的就是发布的；
相同提交幂等返回同一结果。

## 2. 认领指纹（claim fingerprint）

`start_attempt` 事务内写入 attempts（新增列）：

```json
claim_fingerprint = {
  "goal_version": 1,          // mission.goal_version
  "check_version": 1,         // nodes.check_version
  "node_revision": 1,         // nodes.revision（协议01）
  "input_binding_hash": "…"   // sha256(input_binding_json 规范化)
}
```

提交在**慢检查前**先比对一次（早失败），在**正式接收事务内**再比对一次（权威）。

## 3. 两阶段接收（prepare→check→publish→commit）

```
submit_attempt(mid, nid, aid):
  P0 预检（事务外读）：attempt.status=='running' 且指纹匹配当前库；不符→拒绝/幂等返回。
  P1 冻结候选（事务外，文件系统）：workdir 全量复制（排除 __pycache__ 等）到
     <workdir>/../cand_<aid>/；申报工件必须存在于候选内；逐文件 sha256。
  P2 检查（事务外）：在候选目录上跑考卷（逐条三分聚合，协议04语义）。
  P3 发布（事务外，文件系统）：verdict==pass 时把申报文件复制进
     accepted/<nid>/v<next>/，复制后哈希复核；算 manifest_hash。
  P4 正式接收（单事务）：
     重新核验——attempt.status=='running'；mission.goal_version、node.check_version、
     node.revision 与指纹一致；全部绑定快照仍 valid=1。
     任一不符 → 回滚文件不动账本已由 P3 隔离；attempt 置 'rejected'（新终态），
     事件 submit_rejected(原因)；节点状态保持当前真相（cancelled/blocked/…不被覆写）。
     全符 → attempt 终态（accepted/failed/error）+ INSERT assessments（含
     snapshot_id/check_digest/input_binding_hash/env_note）+ INSERT snapshots+
     artifacts + 节点/任务状态迁移 + 事件，同事务。
```

## 4. 幂等与并发提交

- 提交键 = attempt_id。attempt 已终态且已有本 attempt 的 authoritative 证据行 →
  重复提交**返回该证据行结果**（不再产生副作用）。
- 并发重复提交：两线程同时进 P0，其一在 P4 赢；另一在 P4 见 status≠running →
  幂等读取胜者结果返回。
- 取消/收割/维修在检查期间发生：P4 核验失败 → 'rejected'，绝不覆写当前状态
  （四反例之三、之四的修复点）。

## 5. 崩溃点与恢复规则

| 崩溃点 | 现场 | 恢复 |
|---|---|---|
| P1/P2 中 | attempt 仍 running，候选目录残留 | 心跳超时→orphaned→收割→节点回 pending 重派；候选目录随工作目录清理 |
| P3 后 P4 前 | accepted 有文件、无 DB 行 | 孤儿文件无害（版本号取自 DB max+1，不重用）；可由清理例程回收 |
| P4 中 | 事务回滚 | 等同 P3 后 P4 前 |

**不变量**：正式接收成功 ⇒ accepted 文件齐备且哈希=检查时哈希；检查内容≠发布内容的
窗口不存在（检查即跑在候选上）。

## 6. 判决分类与重试记账（第1步配套）

attempt 终态分类列 `category`：
`accept | fail(产物失败) | error(考卷/环境) | cancel | orphan | reject`。
产物重试额度只计 `fail`：允许派发 ⇔ 该节点 fail 类终态数 ≤ max_retries（默认 2，
即首试+最多两次重试）。error/cancel/orphan/reject 不耗额度。预算（calls/cost）持久
在 `missions.budget_json`，重启不重置；ERROR 只记诊断不吞预算余额。

## 7. 动作回执（第2步配套）

`action_receipts.key` = 明确请求身份（动作:任务:节点:参数摘要）。
失败/异常**不落回执**（允许重试），成功才登记；重复请求命中回执直接返回首次结果，
不盲目重复副作用。回执行增加 `status` 列（done|failed 供查询），默认 done。
