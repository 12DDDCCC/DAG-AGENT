# 协议 02：输入绑定——v3.2 冻结版

> 冻结日期：2026-10-03。修订五步第 1/2 步最小协议之二。

版本：F1（冻结）

## 1. 目的

执行者拿到的输入**确定且可验证**：认领时解析并固定依赖的完整快照（协议01），
播种前逐文件验摘要；缺件/损坏/越界/所需版本失效一律拒绝，**禁止悄悄换最新版本**。
修复"deps 叶子无输入""多文件只播末件"。

## 2. 绑定时刻与来源解析

`start_attempt` 在**认领事务内**解析输入并写入 `attempts.input_binding_json`：

```json
[{"source": "n2", "snapshot_id": 3, "manifest_hash": "9f86…",
  "files": ["data.csv", "schema.json"], "role": "dep|child"}]
```

来源解析规则：
- **叶子节点**：每个执行依赖 d → 源节点 s =（d 属于 OR 组（第3步）→ 该组当前赢家；
  否则 d 本身）。取 s 的**最新 valid 快照**；无 valid 快照 → 认领拒绝（依赖未满足）。
- **整合节点**：源 = 全部普通孩子 + 各 OR 组赢家（第3步），同样取最新 valid 快照。
- `expected_version`（依赖表既有列）≠None 时绑定该指定快照号，不存在或已失效则拒绝。

绑定一旦写入即冻结：执行期间上游修订不影响本次输入（迟到修订走失效重验，第2/4步）。

## 3. 统一播种（叶子与整合同规则）

派发执行前，调度器把每个绑定快照的全部文件播种到工作目录：

```
<workdir>/inputs/<source_node>/<rel_path>     # 完整快照，非末件
```

播种前逐文件校验 sha256 与 manifest 一致；任何缺件/不匹配 → 本次尝试终止为
`error`（考卷/环境类，不耗产物重试额度），节点转 **blocked**（防热循环），
事件 `seed_invalid`，人工处置后重派。**禁止**改绑最新版继续跑。
（F1 勘误 2026-10-03：原文"回 pending"改为 blocked——pending 会在调度循环里
 立即重派造成热循环；blocked 与考卷 error 语义一致走人工/维修通道。）

## 4. 越界防护

- 源路径解析后必须以**路径组件包含**（`Path.is_relative_to`）位于 accepted 根内；
  字符串前缀判定废弃（同前缀兄弟目录、`..`、绝对路径、链接逃逸均拒绝）。
- 播种目标路径同样按组件校验，rel_path 内出现 `..` 或绝对段即拒绝。

## 5. 尝试记录与证据

- `attempts.input_binding_json` = 第 2 节清单；提交时（协议03）整体哈希
  `input_binding_hash` 写入 assessments——证据可回答"当时看的是哪几份输入"。
- 复用依据：未受影响节点复用旧证据时（增量重验），校验其绑定快照仍 valid=1
  并在事件 `evidence_reused` 里记录 snapshot_id 依据。

## 6. 示例

叶子 n3（deps=[n2]）认领：
```
input_binding_json=[{"source":"n2","snapshot_id":3,"manifest_hash":"9f86…",
                     "files":["data.csv","schema.json"],"role":"dep"}]
```
播种后工作目录：
```
inputs/n2/data.csv        ← sha256 校验通过才落盘
inputs/n2/schema.json
```
整合根 n1（孩子 n2、n3+n4 同组）认领：
```
input_binding_json=[{…n2…,role:child},{…组赢家…,role:child}]
```
